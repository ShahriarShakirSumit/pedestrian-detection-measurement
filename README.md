# Pedestrian Detection for Intelligent Transportation: Code and Results

This repository contains the code and derived results for the paper "Pedestrian
Detection for Intelligent Transportation: A Measurement-Based Review of
Robustness, Error Structure, and Deployment Cost" by Shahriar Shakir Sumit,
Murat Tahtali and Seyedali Mirjalili.

The study evaluates 46 pedestrian detectors on COCO person, on NightOwls night
driving and on registered visible and infrared pairs from LLVIP. Each detector
is run once per benchmark, and every analysis reuses that frozen set of
detections, so the evaluator varies while the detector does not. All result
tables and figures in the paper are generated by the scripts in this
repository from the stored result files. No measured value is entered by hand.

## Repository structure

| Path | Contents |
|---|---|
| `code/` | Dataset preparation, inference, evaluation, statistics, timing, fine-tuning, table and figure scripts |
| `results/` | Derived result files behind every result table and figure |
| `CHECKPOINTS.md` | The 46 detectors and the checkpoint each was loaded from |
| `environment.yml` | Full conda environment used for all results |
| `requirements.txt` | Pinned versions of the main Python packages |
| `MANIFEST.sha256` | SHA-256 checksums of every file in the repository |

## Requirements

The results were produced with Python 3.10.20, PyTorch 2.6.0 with CUDA 12.4,
torchvision 0.21.0 and Ultralytics 8.4.126 on a single NVIDIA RTX 3070 (8 GB).

```bash
conda env create -f environment.yml
conda activate hod
```

## Reproducing the tables and figures from stored results

This step needs neither the datasets nor a GPU.

```bash
python code/make_tables.py --outDir out
python code/make_appendix_tables.py --outDir out
python code/unfold_tables.py --tablesDir out
python code/figures.py --results results --outDir figures
for g in gen_modality_adapt gen_nightowls gen_tfig2 gen_tfig3 gen_tfig9; do python code/$g.py; done
python code/audit_numbers.py
```

The generated tables contain the same values and captions as the tables in
the paper. Only their layout differs, since float placement, font size, landscape pages and column widths
were set for the journal page. Tables 1 to 6 of the paper summarise the
literature and the evaluation settings and are not generated. Figures are
written to `figures/`, and SVG output can be converted to PDF with `cairosvg`.
`audit_numbers.py` checks the numeric statements in the paper against the
result files. The qualitative track figure (`gen_qualitative.py`) is drawn from
NightOwls frames and therefore needs the dataset.

## Preparing the datasets

The datasets are not redistributed here. `code/prepare_datasets.sh` downloads
them from their providers, arranges them in the layout the scripts expect and
checks every file against the SHA-256 checksum of the copy used for the
published results (`code/dataset_checksums.sha256`). Downloads resume after an
interruption, and files that are already present and verified are skipped.

```bash
export DATA_ROOT=/path/to/datasets
bash code/prepare_datasets.sh                  # all datasets
bash code/prepare_datasets.sh coco kaist       # selected datasets
```

| Dataset | Source | Download size |
|---|---|---|
| COCO 2017 validation | images.cocodataset.org | 1.1 GB |
| NightOwls validation | Visual Geometry Group, University of Oxford | 57.5 GB |
| LLVIP | Hugging Face mirror of the LLVIP release | 4.0 GB |
| KAIST evaluation kit and published detections | MLPD repository | 0.1 GB |

Each dataset remains under its provider's licence and terms of use. The
resulting layout is:

```
$DATA_ROOT/coco/val2017/
$DATA_ROOT/coco/annotations/instances_val2017.json
$DATA_ROOT/coco/annotations/person_keypoints_val2017.json
$DATA_ROOT/nightowls/nightowls_validation/
$DATA_ROOT/nightowls/annotations/nightowls_validation.json
$DATA_ROOT/llvip/LLVIP/{visible,infrared,Annotations}/
$DATA_ROOT/kaist/eval_kit/
$DATA_ROOT/kaist/published_detections/
```

Torchvision weights are downloaded automatically on first use. The Ultralytics
checkpoints are listed by file name in `CHECKPOINTS.md` and should be placed in
one directory:

```bash
export ULTRA_WEIGHTS=/path/to/ultralytics_checkpoints
```

## Running the full pipeline

### Inference

```bash
bash code/run_full_sweep.sh
```

The sweep writes one detection file per detector for COCO person (41
Ultralytics and 5 torchvision detectors), runs the LLVIP visible and infrared
evaluation and writes the NightOwls detections. Completed stages are skipped on
a restart. The raw detection files total 2.1 GB and are excluded from the
repository by `.gitignore`.

### COCO analyses

```bash
bash code/rerun_all_analyses.sh
```

This runs protocol sensitivity, rank stability, the individual protocol axes,
the degradation subsets, the error decomposition, the inversion threshold,
pairwise significance with 50,000 bootstrap replicates and Holm and
Benjamini-Hochberg correction over 1035 pairs, calibration, and significance
against protocol stability. The script stops unless it finds exactly 46
detection files. Outputs are written to `results/`, so `git diff results/`
shows any difference from the published values.

### NightOwls sequence measures

```bash
python code/nightowls_eval.py \
  --annFile $DATA_ROOT/nightowls/annotations/nightowls_validation.json \
  --detDir results/nightowls/detections \
  --out results/nightowls/nightowls_results46.json
python code/same_k_diff_r.py
python code/verify_proposition.py
python code/qualitative_track.py \
  --annFile $DATA_ROOT/nightowls/annotations/nightowls_validation.json \
  --detDir results/nightowls/detections \
  --out results/nightowls/qualitative_track.json
```

`same_k_diff_r.py` counts detector pairs that miss the same number of frames of
a track but differ in the longest unbroken miss run. `verify_proposition.py`
checks the bounds of the proposition on longest miss runs, both exhaustively on
short tracks and on real tracks.

### Adaptation on LLVIP

```bash
bash code/run_infrared_sweep.sh
python code/rq7_finetune.py --root $DATA_ROOT/llvip/LLVIP --model fcos_r50_fpn \
  --out results/finetune/rq7_finetune_fcos_r50_fpn.json
```

The first command fine-tunes the five torchvision detectors on the infrared
channel. The second shows the visible-channel run for one detector. The seed,
schedule and split sizes are stored in each result file.

### Deployment cost

```bash
python code/rq4_timing.py --image $DATA_ROOT/coco/val2017/000000000139.jpg \
  --out results/rq4_timing/rq4_torchvision.json
python code/rq4_timing_ultralytics.py --image $DATA_ROOT/coco/val2017/000000000139.jpg \
  --weightDir $ULTRA_WEIGHTS --merge results/rq4_timing/rq4_torchvision.json \
  --out results/rq4_timing/rq4_rtx3070_all46.json
python code/rq4_flops.py --weightDir $ULTRA_WEIGHTS --out results/rq4_timing/rq4_flops.json
```

Every detector is timed with the same boundary. The image is decoded once,
before timing, and the timed interval covers pre-processing and transfer to the
GPU, the forward pass including NMS, and copying the detections to the host.
Latency is specific to the machine on which it is measured. The published
values were measured at batch size one on an NVIDIA RTX 3070, and the full
software and hardware record is stored in
`results/rq4_timing/rq4_rtx3070_all46.json`. GFLOPs are independent of the
hardware.

### KAIST re-evaluation

`kaist_eval_published.py` scores the published detection files of five
multispectral detectors (MLPD, ARCNN, CIAN, MSDS-RCNN and MBNet) under a single
protocol, using the evaluation kit of the MLPD repository
(https://github.com/sejong-rcv/MLPD-Multi-Label-Pedestrian-Detection).
`validate_mr_implementation.py` checks the miss-rate implementation in
`protocols.py` against that reference evaluator.

```bash
python code/kaist_eval_published.py --evalKit $DATA_ROOT/kaist/eval_kit \
  --annFile $DATA_ROOT/kaist/eval_kit/KAIST_annotation.json \
  --rstFiles $DATA_ROOT/kaist/published_detections/*_result.txt \
  --out results/kaist_published_reeval/kaist_published_reeval.json
```
